# Safety Model, Operational Guarantees & Disclaimers

This document outlines the safety architecture, threat mitigations, and emergency rollback procedures implemented in the Antigravity Context Patcher.

---

## 1. Safety Principles & Operational Guarantees

### Principle 1: Fail-Closed Binary Generation
The patcher relies on structural analysis rather than hardcoded assumptions. During planning:
- If any instruction sequence or signature matches zero times or more than once ($N \ne 1$), the scanner **aborts immediately** with an error.
- Zero bytes are written if any structural precondition fails.

### Principle 2: Complete Database Isolation
- Antigravity stores conversation histories, session states, and workspace embeddings in local SQLite databases (`*.db`, `*.db-wal`, `*.db-shm`).
- **The Context Patcher and Token Monitor never touch, modify, or lock these databases.**
- All runtime state inspection is conducted strictly via memory-safe, read-only Connect-RPC queries.

### Principle 3: Out-of-Process Staging & Atomic Promotion
- The patcher never patches an executable while it is executing.
- Patched binaries are generated exclusively in an isolated `staging/` directory.
- Binary replacement is handled by the guarded script `scripts/apply-checkpoint-on-exit.ps1`, which:
  1. Waits for all active Language Server processes to terminate.
  2. Creates a timestamped SHA-256 backup in `backups/`.
  3. Copies the staged file into production atomically.
  4. Verifies the SHA-256 hash of the copied file.
  5. Rolls back immediately if the post-copy hash does not match.

### Principle 4: Zero Credential Retention
- Connect-RPC discovery reads the ephemeral session port and CSRF token generated by the running Antigravity IDE process.
- These tokens exist only in memory during runtime and are **never** logged to disk, persisted, or transmitted externally.
- No network requests are made outside the local loopback interface (`127.0.0.1`).

## 2. Emergency Rollback Protocol

If the language server fails to start, crashes, or exhibits unexpected behavior after applying a patch:

### Step 1: Terminate Any Running Antigravity Processes
```powershell
Get-Process -Name "language_server_windows_x64" -ErrorAction SilentlyContinue | Stop-Process -Force
```

### Step 2: Restore Authentic Baseline from Backup
The backup directory (`backups/`) contains timestamped backups of the original executable created prior to patching:

```powershell
$ProductionPath = "D:\Antigravity IDE\resources\app\extensions\antigravity\bin\language_server_windows_x64.exe"
$LatestBackup = Get-ChildItem -Path "backups\*.exe" | Sort-Object LastWriteTime -Descending | Select-Object -First 1

if ($LatestBackup) {
    Copy-Item -Path $LatestBackup.FullName -Destination $ProductionPath -Force
    Write-Host "Restored baseline from $($LatestBackup.Name)"
}
```

### Step 3: Verify Restored Binary Hash
Verify that the production binary has returned to its authentic unpatched hash:
```powershell
Get-FileHash -Path "D:\Antigravity IDE\resources\app\extensions\antigravity\bin\language_server_windows_x64.exe" -Algorithm SHA256
```
Expected baseline hash:
`ec2f03ba0fe00630d49b035c2477b549c48fba0d8cc920dfe2d588f001d239b6`
