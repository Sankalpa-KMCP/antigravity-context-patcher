# Security Policy

## Reporting Security Vulnerabilities

The security and privacy of developer workflows are paramount. If you discover a security vulnerability or sensitive data exposure risk in this repository, please report it privately rather than opening a public issue.

- **Private Disclosure:** Please report any critical issues via GitHub Security Advisories or by emailing the project maintainers directly.
- **Response Target:** We aim to acknowledge receipt of security-related reports within 48 hours and provide a resolution timeline promptly.

---

## Security Architecture & Local Safety Guarantees

This project deals with reverse-engineering and local binary patching of Antigravity IDE executables. The following safety guarantees are strictly engineered into this tooling:

### 1. Zero Database Modification Policy
- The patcher and token monitor **never** write, modify, delete, or lock user conversation databases (`*.db`, `*.db-wal`, `*.db-shm`).
- All trajectory and usage metadata is obtained exclusively via read-only Connect-RPC queries (`GetAllCascadeTrajectories`, `GetCascadeTrajectoryGeneratorMetadata`).

### 2. Isolated Staging & Backup Protocols
- The patcher never patches a live running executable in place.
- Candidate binaries are generated in a sandboxed `staging/` directory and verified bit-for-bit before staging.
- The apply-on-exit script (`scripts/apply-checkpoint-on-exit.ps1`) verifies that target processes are terminated, calculates and logs a pre-patch SHA-256 backup to `backups/`, atomically promotes the file, and performs post-copy verification with automatic rollback if any check fails.

### 3. Read-Only Default Verification
- Verification scripts (`scripts/verify-patch.js`, `patcher/src/verifier.js`) operate in strictly read-only mode (`r` flags), opening binaries only to calculate cryptographic hashes and inspect specific instruction immediates.

### 4. Zero Credential Retention
- Connect-RPC discovery reads the ephemeral session port and CSRF token generated by the running Antigravity IDE process.
- These tokens exist only in memory during runtime and are **never** logged to disk, persisted, or transmitted externally.
- No network requests are made outside the local loopback interface (`127.0.0.1`).

## Scope & Limitations

This tooling is strictly designed for local development, research, and inspection. Users are responsible for ensuring that their use complies with their local terms and applicable software licenses.
